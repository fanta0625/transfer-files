# 跃传（YueTransfer）

跃传是一个面向文件传输的 Linux 桌面客户端：左侧浏览本机目录，右侧浏览远程目录，通过一条可配置的 SSH 中转链上传或下载文件和目录。名字取“跃过中转节点、完成传输”之意。

项目使用 Rust + Slint，内部可执行文件和安装包名仍为 `transfer-files`，配置目录也保持 `~/.config/transfer-files/`，升级不影响已有配置。

## 适合什么场景

- Linux 电脑需要经过一级或多级 SSH 跳板机访问家里的 Windows / Linux 电脑。
- 希望在同一个窗口里浏览两端目录、勾选多个项目并直接传输，而不是在多台机器之间手工执行多次 `scp`。
- 网络不稳定，传输中断后希望重新发起时从已完成部分继续，而不是从头复制。
- 需要按标签保存多套连接配置，并在不同连接之间切换而不打断后台任务。

## 与 Xshell 这类终端工具相比

Xshell 等工具以交互式终端会话为中心，文件传输通常依附于终端窗口或额外的 SFTP 会话。跃传不提供终端模拟，而是把文件传输作为主界面：

- **可视化多跳传输**：按连接顺序填写中转节点，界面直接浏览和传输最终目标；每一段仍使用普通 SSH/SFTP，不需要端口转发或远端常驻服务。
- **Windows / Linux 混合连接**：每个中转节点和目标都可单独选择系统类型，Linux 客户端可以连接 Windows 或 Linux 目标。
- **多个标签同时连接**：每个标签有独立的目录、选择、认证状态和任务；切换标签不会中断后台传输，不同标签可以并行传输。每个标签同一时间执行一个任务。
- **校验后断点续传**：重新选择相同源和目标时，先校验已有暂存的前缀 SHA-256，再从匹配位置继续；每段完成后核对完整清单，最终暂存校验通过才发布。
- **密码和 SSH 密钥认证**：支持密码、私钥和加密私钥口令；密码通过认证弹窗输入，经受限终端会话交给 OpenSSH，不写入磁盘、命令参数或日志。

这些差异只是在文件传输这一侧的使用方式不同。需要交互式 shell、端口转发或终端复用时应使用专门的终端工具。

## 已实现功能

- 左侧本机目录、右侧远程目录的双栏浏览，支持返回上级、路径输入、刷新、多选、内部拖拽和外部拖入。
- 直连或最多 7 级中转节点，加上最终目标；所有节点都按 SSH / SFTP 逐级连接。
- 文件与目录上传、下载；支持中文和空格路径、空目录、零字节文件。
- 多标签连接配置持久化；标签之间凭据隔离。
- 密码缓存策略：5 分钟过期、本次程序运行期间有效、一次性不缓存。口令和密码不写入配置文件。
- 私钥路径可按连接发起端分别设置；加密私钥会单独询问口令。
- 传输区域实时输出：当前文件、百分比、已传输/总大小、速度、预计剩余时间，以及成功、失败、跳过和续传状态。
- 输出自动滚动，可取消自动滚动向上查看历史；每个标签的输出独立保存，并提供“清空”按钮。
- 排查传输失败时，在下方勾选“诊断模式”后重新传输。日志以 `[诊断]` 标记显示每条命令的执行节点及终端输出，不按错误关键词筛选；伪终端中的 stdout/stderr 合并显示。输出在命令结束或进入下一次认证时刷新，认证提示、已输入的密码/口令和内部编码响应会过滤。开关按标签独立保存于本次运行，传输中不可切换；诊断模式保留最近约 10,000 行，可在输出框中选择复制，不自动写入磁盘。分享日志前请留意其中的主机名和文件路径。
- 任务可取消；取消后已完成的文件保留，未完成文件不会发布为目标文件。

## 运行环境

Linux 客户端（当前远程操作仅支持 Linux 客户端）：

- Rust / Cargo 1.95 或更新版本（仅从源码构建时需要）。
- OpenSSH `ssh`、`sftp` 和 Python 3。
- 桌面环境使用 X11；打包后的启动脚本默认设置 `WINIT_UNIX_BACKEND=x11`。

远端节点：

- Linux：OpenSSH 服务端（含 SFTP 子系统）、Python 3；中转节点还需要 `ssh` / `sftp` 客户端和分配终端的能力。
- Windows：OpenSSH 服务端（含 SFTP 子系统）、Windows PowerShell 5.1；中转节点还需要 `ssh` / `sftp` 客户端和分配终端的能力。

不使用 ProxyJump、端口转发或 agent 转发，也不在远端安装常驻程序。

## 从源码运行

```bash
cargo run --locked
```

或使用启动脚本（Release 程序不存在时才构建）：

```bash
bash scripts/run.sh
```

传入两个本地目录可以强制进入本地验证模式：

```bash
cargo run --locked -- "$HOME/Downloads" "$HOME/Documents"
```

## 打包与安装 deb

在目标 Linux 电脑上安装打包工具：

```bash
sudo apt install dpkg-dev python3
bash scripts/build-deb.sh
sudo apt install ./target/debian/transfer-files_*.deb
```

脚本构建本机架构的 Release 程序，并安装：

- 可执行文件与 `/usr/bin/transfer-files` 启动包装脚本；
- `/usr/share/applications/transfer-files.desktop` 桌面入口；
- `/usr/share/icons/hicolor/` 下 16–512 像素 PNG 和 SVG 原图；
- 应用菜单中的“跃传”，分类为网络 / 文件传输。

安装后可从 KDE 等应用菜单搜索“跃传”启动，也可以执行 `transfer-files`。卸载使用 `sudo apt remove transfer-files`，个人配置会保留。

若已经编译好本机程序，可跳过构建：

```bash
bash scripts/build-deb.sh --binary /绝对路径/transfer-files
```

## 连接与传输

1. 点击“+ 新连接”，在“远程设置”中填写标签名称、按顺序排列的中转节点和目标；不需要中转时留空。
2. 每个节点选择 Linux / Windows，填写地址、端口、用户名；私钥可留空。
3. 保存后点击“读取远程目录”发起连接。首次连接需按提示核对主机指纹。
4. 在左栏选择本机文件，点击“左侧选中 → 远程”上传；在右栏选择远程文件，点击“远程选中 → 左侧”下载。也可以直接拖拽。
5. 传输过程中可切换标签，后台任务继续；需要认证的标签会显示“待认证”。

密码不写入配置、命令参数或环境变量。认证弹窗最多等待两分钟；目录读取空闲超时 60 秒；传输和大文件哈希操作空闲超时 30 分钟。

## 实时传输输出

窗口下方的“传输输出”从实际传输过程取样，不使用模拟进度：

- 文件名和百分比、已传输量 / 文件总大小、当前速度、预计剩余时间；
- “续传”表示检测到校验通过的部分文件；“成功”“跳过”“失败”分别对应当前文件的实际结果；
- 整体进度条和“文件 N/M”按当前 SSH 段统计；多跳任务会标注“第 N/M 段”；
- 取消勾选“自动滚动”后可向上查看历史；输出按标签隔离，每个标签最多保留最近 600 行。

字节进度来自 OpenSSH SFTP 自身的传输计数；校验阶段只显示“校验并准备”，不会凭空生成百分比。错误信息只保留必要的失败原因，不输出密码、密钥内容或完整 SSH 命令参数。

## 断点续传与文件边界

重新启动程序后，选择相同源文件/目录、连接配置和目标目录再次传输即可续传；没有额外的“继续”按钮。

1. 读取源清单并计算 SHA-256，源内容、路径、连接链和传输方向共同确定任务标识。
2. 查找该任务的私有暂存目录；对已有的部分文件计算哈希，并与源文件对应长度的前缀比较。
3. 只有前缀一致才使用 SFTP `reget` / `reput` 接续；完整且匹配的文件跳过，不同内容不会拼接。
4. 每一段传输后核对目录清单和文件哈希。
5. 最终在目标父目录暂存，再用禁止覆盖的方式发布；同名目标内容相同则跳过，不同则报错。

限制：

- 不覆盖同名目标，目录不做增量合并。
- 不传输符号链接、Windows junction 和特殊文件；文件名不能包含控制字符。
- 不保留源文件权限、所有者或时间戳。
- 读取/哈希清单上限 16 MiB，超大目录请分批传输。
- 暂存和发布需要额外磁盘空间；Linux 发布要求文件系统支持 `RENAME_NOREPLACE`。
- 传输期间源文件变化会导致校验失败，不会发布不匹配的内容。
- 同一应用内完全相同的源和目标不能同时传输，避免争用暂存文件。

更完整的认证、缓存和续传细节见 [连接和断点续传](docs/connection-and-resume.md)。

## 已知边界

- 远程浏览和传输目前只在 Linux 客户端实现；Windows 构建用于本地交互和适配测试。
- 不自动后台重连、不自动恢复任务列表；中断后需要重新选择相同源和目标。
- 不支持从 GUI 拖出到 Dolphin；当前支持 Dolphin 等文件管理器拖入本应用。
- 暂不支持 MFA/OTP 自定义交互。

## 开发检查

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
bash scripts/test-transfer.sh
```

最后一项需要 OpenSSH `sftp-server`，可用 `TF_TEST_SFTP_SERVER=/path/to/sftp-server` 指定。它用隔离的本地 SSH 替身运行真实 SFTP，覆盖直连、多跳、上传下载、部分文件续传和错误前缀拒绝，不连接用户主机。

## 目录结构

```text
src/main.rs                     界面控制、任务事件、传输输出格式化
src/tabs.rs                     多标签配置、标签独立任务与认证状态
src/config.rs                   连接参数校验与保存（不含密码）
src/files.rs                    本地目录读取与可取消复制
src/remote/terminal.rs          Linux PTY、混合系统 SSH 链、认证与进程清理
src/remote/transfer.rs          SFTP 逐段传输、真实进度解析、校验续传与发布
src/remote/operations.rs        临时文件系统操作适配（Python / PowerShell）
ui/app.slint                    双栏界面与传输输出区域
assets/icons/                   Logo SVG 与常用尺寸 PNG
packaging/transfer-files.desktop 桌面入口
scripts/build-deb.sh            deb 打包
```
