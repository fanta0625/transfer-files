# 混合系统连接、认证和续传

## 支持范围

Linux 客户端支持直连、Linux / Windows 混合中转，目标可为 Linux 或 Windows。每个节点手动选择系统类型，旧配置默认 Linux 中转、Windows 目标。不要求 Windows 反向连接客户端，不使用端口转发、ProxyJump 或 agent 转发。

| 位置 | 必需条件 |
| --- | --- |
| Linux 客户端 | Python 3、OpenSSH ssh / sftp |
| Linux 中转 | OpenSSH 服务端及客户端、Python 3、POSIX shell、可分配终端 |
| Windows 中转 | OpenSSH 服务端及客户端、Windows PowerShell 5.1、可分配终端 |
| Linux 目标 | OpenSSH 服务端、SFTP 子系统、Python 3 |
| Windows 目标 | OpenSSH 服务端、SFTP 子系统、Windows PowerShell 5.1 |

远端文件操作脚本随 SSH 命令执行，不安装服务或常驻代理。Windows 命令使用压缩脚本，兼容默认 cmd.exe / PowerShell 命令入口。不同 OpenSSH 版本的 Windows 伪终端和嵌套密码交互仍需在实际机器验收。

## 密码与密钥

- **5 分钟过期**：自输入起计时，每个凭据独立到期，重复使用不续期。
- **永不过期**：仅在本次程序运行期间缓存，关闭程序、修改配置或操作失败时会清除。不是保存到磁盘。
- **一次性**：每次认证都重新询问，不缓存。目录扫描、各段传输和校验可能发起多个 SSH 连接，所以一个任务也可能多次询问。频繁传输建议使用密钥或 5 分钟缓存。

私钥路径可留空，OpenSSH 会使用默认密钥、当前发起端的 agent 或密码。指定私钥后添加 `IdentitiesOnly=yes`；加密私钥会单独询问口令，口令和登录密码分别缓存，采用相同过期策略。

**私钥必须位于发起连接的电脑**：本地 → A → B 时，A 的私钥路径指本地文件，B 的私钥路径指 A 上的文件。不会自动上传私钥，不会转发本地 agent。Windows 路径推荐 `C:/Users/user/.ssh/id_ed25519`；Linux 使用绝对路径，例如 `/home/user/.ssh/id_ed25519`。

每一段主机密钥由发起连接端的 known_hosts 验证；首次使用仍须核对指纹。中转机需要可信，因为文件会明文暂存，且中转机运行下游 SSH 客户端。

## 如何恢复中断

重新启动程序也可以恢复：选择相同源文件/目录、连接配置和目标目录，再次上传或下载即可。没有后台自动重连、恢复任务列表或额外“继续”按钮。

1. 读取源清单，计算每个文件的 SHA-256。源内容、路径、连接链和传输方向共同决定任务标识。
2. 逐段寻找私有暂存目录。对每个部分文件计算哈希，与源文件对应长度的前缀比较。
3. 只有前缀一致才用 SFTP `reget` / `reput` 接续。完整且匹配的文件跳过，缺失文件从头传；不同内容不会强行拼接。
4. 每一段完成后核对整个目录清单和所有文件哈希。
5. 最终在目标同一目录下暂存，再以禁止覆盖的文件系统操作发布文件或整个目录。目标已有相同内容则跳过，不同内容则报错，不合并目录。
6. 成功后清理本任务暂存。失败或取消保留数据，错误信息显示位置；清理失败会明确提示文件已经送达。

中转暂存通常在 Linux `~/.cache/transfer-files/.transfer-files-<任务标识>` 或 Windows `%LOCALAPPDATA%/transfer-files/.transfer-files-<任务标识>`。最终暂存位于目标父目录，避免跨文件系统发布。不会保存密码、私钥内容或目录浏览快照。

源内容改变会生成新标识，旧暂存不会自动删除。需要释放空间时，在无传输任务运行时，按错误日志中的确切路径清理该任务目录；不要删除其他任务或整个用户目录。

## 边界

- 拒绝符号链接、junction、特殊文件以及含控制字符的文件名。目标系统不支持的文件名会报错。
- 续传需要重新读取源和已有部分计算哈希，会产生磁盘读取，不保证立即显示网络进度。GUI 当前仍显示选中项目计数。
- 文件在校验/传输期间变化会导致校验失败，不会发布不匹配的结果；没有文件系统快照能力。
- 读取目录空闲超时 60 秒；传输/哈希操作空闲超时 30 分钟；认证弹窗最多等待两分钟。
- 清单响应上限 16 MiB；超大目录应分批传输。源和暂存需要稳定且非共享攻击者可写的目录。
- 暂存和发布分别需要空间与写权限。Linux 发布要求文件系统支持 `renameat2(RENAME_NOREPLACE)`，不支持时报告错误，不退化为覆盖。
- 仍不支持自定义 MFA/OTP。Windows 客户端的远程操作本身未实现。

## 验证方式

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
bash scripts/test-transfer.sh
```

最后一项需要 OpenSSH `sftp-server`，可用 `TF_TEST_SFTP_SERVER=/path/to/sftp-server` 指定。测试以隔离的本地 SSH 替身运行真实 SFTP，不连接用户主机，不读写用户凭据；覆盖直连、多节点、上传下载、部分文件续传、错误前缀拒绝和发布冲突。它不是实际 Windows/Linux 混合网络部署的验收证明。
