# 经 SSH 跳板机中转的双栏文件传输工具

文档日期：2026-10-21  
状态：已实现 Rust + Slint 本地双栏原型、远程配置、Linux 两段 SSH 认证、Windows 目录浏览以及文件/目录两向传输；Dolphin 拖出尚未接入。目标机已通过最小 Slint 窗口测试，新增远程功能待实际链路验收。

## 1. 背景与目标

用户在公司 Linux 电脑上工作，桌面环境为 KDE，文件管理器为 Dolphin。家里电脑运行 Windows。公司电脑通过公网 SSH 登录跳板机，跳板机通过 Tailscale 网络访问家里 Windows。

当前手动操作：

- 下载：Windows 将文件上传到跳板机，公司 Linux 再从跳板机下载。
- 上传：公司 Linux 将文件上传到跳板机，跳板机再将文件上传到 Windows。

目标是将两段传输自动化，通过图形界面浏览和拖拽文件，按任务认证、传输并断开连接，不再手动执行多次 SCP。

## 2. 已确认的环境与约束

| 项目 | 需求或事实 |
| --- | --- |
| 客户端 | 公司 Linux，KDE Dolphin |
| 远端 | 家里 Windows，已有可用 SSH 登录与文件传输路径 |
| 中转 | 公网可访问的 SSH 跳板机 |
| 家庭网络 | Windows 与跳板机通过 Tailscale 联网 |
| 公司限制 | 不安装隧道类软件；方案不依赖公司电脑上的 Tailscale、VPN 或 SSH 端口转发 |
| 传输路径 | 保留现有两段 SSH/SCP 和跳板机暂存方式 |
| 连接生命周期 | 按需建立；一批任务完成、失败退出或取消后释放对应连接 |
| 认证预期 | 每批分别输入跳板机、Windows 密码，尽量每端只询问一次 |
| 交互预期 | 图形浏览、双向拖拽、可见进度、传完断开 |

不将短时断开等同于关闭 Tailscale 服务或停止 Windows SSH 服务。需要关闭的是本应用建立的会话和子进程。

## 3. 界面方案与范围

### 3.1 建议的第一版方案

在公司 Linux 上运行一个自有双栏 GUI：

- 左侧：公司 Linux 本地目录。
- 右侧：家里 Windows 目录。
- 下方：任务队列、两段传输进度、状态和错误信息。

Windows 不需要运行 GUI。右侧是客户端对 Windows 目录数据的展示，不是远程桌面窗口。

这是讨论后采用的原型基线，完整原型待目标机验收。用户最初也提出过两个独立文件窗口的交互需求；第一版优先用双栏满足同一操作目的。

当前程序有两种模式：配置有效时左栏为本地、右栏为 Windows 远程目录；传入两个本地目录参数时强制使用本地验证模式。后者保留内部双向拖拽、Dolphin 拖入、后台复制与取消。远程模式支持本地与远程之间的文件/目录上传下载，远程路径不会被误用为本地路径。

“远程设置”仅保存非敏感参数：跳板机地址、端口、用户名，Windows 的 Tailscale 地址、SSH 端口、用户名和默认目录。配置文件默认位于 Linux 的 `~/.config/transfer-files/config.conf`。保存与启动不自动连接；点击读取、进入目录、上级或刷新才连接，GUI 请求两端密码或私钥口令。每次目录读取结束立即断开，内存仅保留最近一次成功读取的目录快照；失败时保留旧快照。

### 3.2 第一版功能

1. 已实现：配置跳板机与 Windows 的地址、端口、用户名和默认远端目录。
2. 已实现：本地和远端目录浏览、返回上级、路径输入、目录排序、大小与修改时间显示。
3. 已实现：每次远端读取使用两段普通 SSH，GUI 处理主机指纹和密码，完成后断开。
4. 已实现：最近一次成功的远端目录快照保留在内存并标记读取时间，失败保留旧快照。
5. 已实现：本地与远端面板之间的文件/目录上传下载、Dolphin 拖入远端、两段 scp -r 和任务进度。
6. 未实现：远端多目录持久缓存、断点续传、复杂冲突处理和 GUI 拖出到 Dolphin。

### 3.3 后续或待确认功能

- 从 GUI 拖出远端文件到 Dolphin，落下后开始下载：属于独立需求，不能以 GUI 内双向拖拽宣称已经支持。
- Dolphin 集成可通过专用 KIO worker/协议实现，需要确认客户端是否允许部署，以及 KDE/KIO 版本。
- 两个独立 GUI 窗口、远端新建目录与重命名可后续细化。
- 断点续传、自动同步、远程编辑、删除文件、跨远端复制不作为第一版默认范围。

## 4. 网络与协议设计

```text
公司 Linux：自有 GUI
    │ 普通 SSH / SCP，公网连接
    ▼
跳板机：执行中转操作、保存临时文件
    │ 普通 SSH / SCP，经现有 Tailscale 网络到达
    ▼
家里 Windows：SSH 服务、文件系统
```

不使用 ProxyJump、SSH -L/-R/-D、SSHFS 或远程桌面作为本方案的基础。

### 4.1 目录读取

SCP 命令不提供目录浏览接口。当前通过 SSH 在 Windows 执行 PowerShell，以带版本和请求标识边界的结构化文本协议返回目录数据：

```text
GUI → SSH 登录跳板机 → 跳板机 SSH 登录 Windows
    → PowerShell 枚举目录 → 结构化目录数据原路返回 → GUI 渲染
```

当前目录协议 v1：

- `TF_LIST_V1_BEGIN_<请求标识>` / `TF_LIST_V1_END_<请求标识>` 包围一个完整结果。
- `P` 行为完整目录路径；`D` / `F` / `L` 行为目录、文件或链接，包含大小、UTC 时间、名称与完整路径。
- 字符串以 UTF-8 编码后 Base64，字段用 TAB 分隔，避免中文、引号、换行文件名与终端横幅混淆。
- 错误以 `TF_ERROR_<请求标识>` 加 Base64 错误文本返回；缺少完整结束边界视为失败，不发布半份目录。
- 请求路径作为 PowerShell 字符串转义后，整个脚本以 UTF-16LE `EncodedCommand` 传递；不拼接裸用户路径到 POSIX shell。

后续扩展时可增加以下字段：

- 协议版本、请求 ID。
- 当前规范化路径、父目录路径、读取时间。
- 文件列表：名称、完整路径、类型、大小、修改时间。
- 明确的成功或失败状态、错误代码和错误描述。

实现要求：

- 使用固定 UTF-8 编码和结构化协议，不解析 `dir` 的终端排版。
- 单项、空列表与多项返回保持一致的数组结构。
- 将数据、诊断信息和密码提示区分开；仅解析版本边界内的数据，不解析登录横幅。
- 正确处理中文、空格、引号、换行及 shell 特殊字符，不将用户路径直接拼入多层 shell 命令。
- 路径规范化应保留 Windows 盘符语义；链接、junction 不默认递归跟随。
- 目录元数据读取不下载文件内容。

### 4.2 文件传输

继续使用两段 SCP 工作流。现代 OpenSSH 的 `scp` 默认底层使用 SFTP；本方案所说的 SCP 指命令/操作流程，不假设使用旧版 SCP 线协议。

上传：

```text
Linux 源文件 → 跳板机任务暂存目录 → Windows 目标目录
```

下载：

```text
Windows 源文件 → 跳板机任务暂存目录 → Linux 目标目录
```

第二段可以由跳板机主动连接 Windows，上传时推送、下载时拉取；不要求 Windows 主动连接公司电脑。

第一版建议逐文件完成两个阶段，再处理下一个文件，降低整批暂存需求。目录需先枚举成任务清单并保存相对层级。具体并发数量在原型验证后决定。

## 5. 认证与连接管理

### 5.1 用户体验

- 拖拽后收集本批所需凭据：跳板机密码、Windows 密码。
- 若本批包含多个文件，不应每个文件或每一段都重新弹框。
- 默认不保存密码到磁盘；仅在本批所需时间内保留认证上下文，结束后释放凭据引用。
- 密码错误时仅重试对应端；首次主机密钥确认、密钥变化等情况不算入“两次密码”的正常流程承诺。

### 5.2 需要先验证的工程难点

简单串联多个 `ssh`/`scp` 进程，不能天然实现一端只输入一次密码。当前目录读取使用 Linux PTY 托管公司电脑的 OpenSSH，跳板机分配终端运行第二个 OpenSSH，Windows 端不分配终端。两端密码与主机密钥确认通过 GUI 响应，读完等待 SSH 进程退出后才发布目录。禁用 SSH 连接复用、端口转发、代理转发及 ProxyJump，不影响用户已有会话。跳板机必须允许分配终端；当前只适配标准密码、公钥与私钥口令，不支持自定义 MFA/OTP 提示。

远程文件传输实现前仍需验证任务级认证与复用方式：

1. 客户端管理 OpenSSH 子进程、受控交互认证和适当的短期连接复用。
2. 跳板机运行任务级辅助程序，管理 Windows 认证与文件操作，通过普通 SSH 会话与 GUI 通信。

第二种需要单独确认跳板机是否允许部署辅助程序。当前目录浏览采用第一种且不部署辅助程序；这不代表传输批次已经验证可行。

无论使用哪一种：

- 密码不得进入命令行参数、配置文件、日志或持久化任务文件。
- 校验公司到跳板机、跳板机到 Windows 两段主机密钥，不默认跳过验证。
- 仅终止本应用创建的任务进程、连接与复用资源，不影响用户已有 SSH 会话。
- GUI 关闭、用户取消、连接超时都必须触发资源释放。

## 6. 离线浏览与按次连接

“随时显示远程目录”与“未认证前完全不联网”不能同时提供实时数据。

明确采用以下规则：

1. 首次打开远端位置、进入未缓存目录或主动刷新，需要连接并认证。
2. 浏览请求完成后释放连接；界面保留目录快照，显示“离线缓存”和时间。
3. 已缓存目录之间切换可不联网，但不能宣称数据实时有效。
4. 从缓存发起传输时重新连接并核实源文件、目标目录与冲突。

当前原型只保留最近一个成功目录的内存快照，尚未实现多目录缓存或断点续传；每次切换目录均重新连接。密码缓存最多 5 分钟，网络空闲 60 秒或认证弹窗两分钟未响应会中止；单次目录输出限制为 16 MiB。
5. 浏览认证与之后传输认证可能分别发生；不承诺首次浏览到传输全流程总共只问两次密码。

如果后续需要“浏览期间保持短会话，传完立即断开”，应作为用户可选行为明确确认，不能默认为长期连接。

## 7. 任务状态与传输语义

建议状态：

```text
待处理 → 等待认证 → 检查源与目标 → 第一段传输
       → 第二段传输 → 校验 → 发布目标文件
       → 清理暂存 → 断开 → 完成
```

任一阶段可进入失败或取消处理。批次结束以所有任务均达到终态且连接已释放为准，不能以文件暂时离开队列作为完成依据。

- 默认拖拽执行复制，不删除源文件；不支持隐式移动。
- 同名冲突提供覆盖、跳过、另存为，并支持对本批应用同一选择。
- 两段进度分别展示；第一段完成不能显示整个任务完成。
- 目标先写入本任务专属临时文件，确认成功后发布为正式名称。覆盖与重命名行为需按 Windows/Linux 实际文件系统测试，不能笼统承诺原子覆盖。
- 至少检查传输退出状态及预期文件大小；需要内容级校验时使用校验和。仅大小一致不等于内容完整性证明。
- 传输时源文件发生变化、源文件消失、目标权限不足应报告具体错误。
- 第一版可失败后重新传输，不把重试称为断点续传。

## 8. 中转文件与失败恢复

- 跳板机使用本应用专属暂存根目录；每批创建不可冲突的任务子目录。
- 暂存目录仅授予必要权限，磁盘空间不足时提前报错。
- 成功后只清理本批明确拥有的文件和目录。
- 第二段失败可短期保留中转数据供重试，界面明确提示保留位置、状态与清理策略。
- 取消时停止本批进程，尝试清理部分文件；网络不可用导致无法清理时记录待清理项。
- 下次连接可按任务记录清理过期残留；不得扫描后误删用户已有文件。
- “已送达但清理失败”与“传输失败”分别展示，避免重复上传已成功文件。
- 日志记录阶段和错误，隐去凭据；持久化记录不含密码。

## 9. 建议模块划分

| 模块 | 职责 |
| --- | --- |
| GUI 文件面板 | 路径导航、多选、拖拽、缓存提示 |
| 本地文件访问 | Linux 目录与目标文件操作 |
| Windows 目录适配 | PowerShell 请求、版本化目录协议、路径转换 |
| 认证与连接管理 | 两端认证、主机密钥、生命周期 |
| 批次调度 | 任务清单、顺序、进度、取消与重试 |
| 两段传输执行器 | SCP 子进程或等价实现、状态采集 |
| 暂存管理 | 任务目录、空间检查、成功与残留清理 |
| 配置与缓存 | 非敏感连接配置、目录快照、任务恢复记录 |

当前原型采用 Rust + Slint 1.18.1，Winit 后端与软件渲染，Linux 使用 portable-pty 管理 SSH 终端。目标为 LoongArch64，已知用户环境是 Loongnix 25、glibc 2.41、X11、Rust/Cargo 1.95.0。最小窗口已由用户验证通过；完整原型需继续验证真实 SSH 链路、目录交互和 Dolphin 拖入。打包方式尚未确定。

采用固定 Slint 版本与 Cargo.lock 控制依赖；不依赖 Qt 或 Skia。若目标机拖放适配验证失败，基于具体问题再评估修复或框架替代。

## 10. 开发顺序

1. 核实目标环境：Linux 发行版、KDE 版本、跳板机系统、Windows/OpenSSH/PowerShell 版本及可部署范围。
2. 原型验证：无端口转发的两层 SSH 认证、结构化目录往返、两段小文件传输和连接释放。
3. 实现批次任务与暂存管理，先通过命令行方式验证行为。
4. 实现双栏 GUI、目录缓存和内部双向拖拽。
5. 加入 Dolphin 拖入上传、目录递归、冲突与失败处理。
6. 在公司 Linux 与实际网络链路中验收。
7. 如需要，再开发 KIO 集成，实现 GUI 拖出到 Dolphin 或直接两个 Dolphin 窗口操作。

## 11. 验收标准

### 核心功能

- 公司电脑不安装隧道软件、不建立 SSH 端口转发即可完成操作。
- GUI 正确显示本地 Linux 和远端 Windows 目录。
- 单文件、多文件、目录可在 GUI 内双向拖拽复制。
- Dolphin 拖入远端面板可上传。
- 普通密码认证成功路径下，同批每端最多输入一次密码；重复文件操作不重复询问。
- 缓存目录明显标记为非实时，刷新会显式触发连接。
- 两段进度、成功与失败状态准确，源文件默认保留。
- 批次终止后没有遗留本应用的活动 SSH/SCP 连接；正常成功后没有本批中转残留。

### 异常与边界

- 中文、空格、引号等文件名及路径正确处理。
- 空目录、零字节文件、大文件、递归目录均能处理。
- 密码错误、主机密钥变化、无权限、磁盘满、网络中断有明确反馈。
- 同名冲突不会静默覆盖，用户取消不会误删原文件。
- 中途退出与清理失败可识别并恢复或清理。
- 传输实际结果和源文件内容核对一致。

外部 Dolphin 拖出下载只有实现并通过单独验收后才标为支持，不计入第一版已实现能力。

## 12. 待确认事项

1. 公司 Linux 是否允许运行自有 GUI，以及可用安装/打包方式。
2. Linux 发行版、KDE Plasma/Dolphin 版本，以及 X11 或 Wayland。
3. 跳板机操作系统、可用工具、暂存空间，是否允许部署任务辅助程序。
4. Windows 使用的 SSH 服务、PowerShell 版本及实际认证方式。
5. 常见文件大小、目录规模、是否要求严格校验和或断点续传。
6. 失败中转文件保留时间，以及目录缓存的保存范围。
7. 是否接受第一版双栏单窗口，以及 Dolphin 拖出下载是否必须首版交付。

上述信息不应通过收集明文密码来确认。连接地址和非敏感环境信息可在实施阶段提供。
